Read this as a map of the existing code. Traces, prompt tracking, local evaluations and feedback are implemented. JSON logs exist locally; the supplied Docker Agent does not collect them. 01 · Learn the signals

One application. Different questions.

A healthy HTTP response, a correct policy answer and a delivered trace are three separate checks.

1Collect

The SDK records; the Agent forwards.

ddtrace-run starts before application imports so supported FastAPI, HTTPX, PyMongo, LangChain and OpenAI calls can be instrumented. init_telemetry() also calls ddtrace.patch_all() during application startup.

PurposeExplain latency across API, retrieval and model calls.
In this repoMac processes send traces to 127.0.0.1:18126; Docker maps that to the Agent’s 8126/TCP. Runtime metrics use 18125 → 8125/UDP.
Operating habitLoad .env into the process before ddtrace-run. Pydantic reading the file does not export SDK settings.

app/core/telemetry.py · app/compose.datadog.yaml

2Identify

Keep service, application and span distinct.

The UI is APM service nexaassist-ui; the API is nexaassist-api. API workflows explicitly set agent_service=settings.dd_service so an upstream UI LLM application name does not regroup their model runs.

PurposeFind API model calls under the same LLM application whether the question came from the UI or directly.
In this repoDatadog propagates tracing headers across HTTP. The API workflow identity is explicit while the distributed APM trace stays connected.
Operating habitStart with service:nexaassist-api env:dev. Do not put an LLM-only span-type filter on an HTTP request search.

app/services/answer.py · app/services/evaluation.py

3Explain

An LLM span carries the generation evidence.

ChatOpenAI uses the Responses API. Automatic instrumentation records supported model calls; prompt_annotation_context() adds a stable prompt ID, version, static chat template and the actual invocation variables.

PurposeReproduce the question, date, product and supplied policy passages used for a generation.
In this repoTemplates come from the existing LangChain prompts. Each citation-repair attempt has its own variables under the same prompt version.
Operating habitInspect the OpenAI provider LLM span for prompt details. Increment the adjacent version constant whenever its template changes.

app/chains/llm.py · app/core/observability.py · app/chains/prompts/answer.py

4Evaluate

Tracing records behavior; Ragas and judges score it.

The evaluated-answer service retrieves and generates once, then scores that answer and its exact assembled context. The batch runner also compares against local golden cases with a structured LLM judge.

PurposeSeparate fast answers from grounded, relevant answers.
In this repoScored values are submitted against an exported workflow span with eval_scope="span". Missing reference data yields an explicit unavailable status, not a fabricated zero.
Operating habitSelect the evaluated workflow’s Evaluations tab. Its child model spans do not automatically inherit the same evaluation scores.

app/evaluation/live.py · app/evaluation/run.py

5Diagnose

Use events and limits honestly.

structlog writes JSON events such as retrieval_completed, answer_completed and model_token_usage. The tracing SDK injects correlation fields when configured. Collection and indexing of those logs are a separate path.

PurposeCorrelate failures and token usage with a request ID in local logs.
In this repoThe current Compose file enables APM and DogStatsD, not a Logs Agent source. Its Docker socket exposes container information, not full macOS host monitoring.
Operating habitTreat JSON endpoints, custom metric export, log shipping and alert creation as separate integrations.

app/core/logging.py · app/api/operations.py

05 · Practice

Three habits that prevent empty screens.

“Load, then trace.”
--env-file .envddtrace-runapplication import

The SDK reads process environment during bootstrap. Settings parsing inside FastAPI is later.

“Host 18, container 8.”
18126 → 8126 / TCP18125 → 8125 / UDP

Mac applications use the published loopback ports. A container on the Compose network uses the Agent’s container address and ports.

“Workflow for scores.”
provider span → prompt / tokensworkflow → evaluations

The score joins use a span ID and eval_scope="span". Opening a sibling or child span can show an empty Evaluations tab.

Revisit the trace-visibility incident

A traced Streamlit client propagated nexaassist-ui as the LLM application name. Both API answer workflows now pass agent_service=settings.dd_service. This makes API generation discoverable under nexaassist-api without discarding the caller’s APM trace.

The SDK regression checks upstream UI identity, both API workflow identities and APM trace continuity.

Run commands from the repository root. Examples contain synthetic policy data. Live questions and evaluations call the configured providers and can incur usage charges.

Start the repository’s Docker Agent.

Use app/compose.datadog.yaml rather than replacing it with the source guide’s generic Compose stack. The API and UI run on the Mac in this setup.

Start the API and UI in separate terminals.

Terminal A · FastAPI

If you see…Check this first
No API tracesSDK loaded before imports; actual receiver URL :18126; fresh HTTP request; correct organization, service and time window.
No LLM tracesA real model call occurred; DD_LLMOBS_ENABLED=true; select the API application and include the workflow.
Prompt but no scoresAn ordinary answer does not run Ragas. On an evaluated answer, open the workflow rather than only its provider span.
API shows in APM, UI-origin models disappearBoth API workflows set the explicit API identity. Restart the API after the fix; historical traces keep their original application.
No logs in DatadogThe current Docker setup has no Logs Agent source. Correlation injection alone does not ship log files.
No retrieval metric in Metrics ExplorerThe JSON metrics endpoints are not exported or scraped. Runtime metrics and automatic APM metrics are different signals.

Log shipping would require an enabled Logs Agent and an explicit readable file/container source.
